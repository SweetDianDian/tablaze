# Browser Use variants: scope and next comparison track

Audit date: **2026-09-22**. This supplements [the comparison contract](BROWSER_USE_COMPARISON.md); it does not change its pins, acceptance gates, or any measured report. Source inspection and official documentation establish exposed capabilities, not task reliability. No browser, model, installation, or paid service was started for this audit. The only executed CLI probe was `codex exec --help`.

**2026-09-23 execution follow-up:** the [native Codex/MCP development smoke](CODEX_NATIVE_MCP_SMOKE.md) has now run against the fixed Harness source. Two visible tasks passed on each arm; this adds measured evidence for this tool track without changing the original audit date, the other `not_run` variants, or the broader acceptance gates. The installed `0.1.13` wheel differed from the pinned source in five Python files, including `mcp_server.py`; the follow-up executed the pinned source through `PYTHONPATH` and records its archive hash.

The [expanded MCP variants report](CODEX_MCP_VARIANTS_V2.md) adds Browser Use `--cli-mcp` and structured `--mcp`, plus a virtual-list task. The direct structured tools did not complete the nested-scroll task in one attempt; CLI-MCP and Harness did. With the structured server's optional nested Agent routed through the same Codex model and a longer MCP tool timeout, its second full-path attempt also completed. These remain visible development samples, not a frozen superiority evaluation. The JS Harness, Pi, and Cloud tracks are still unmeasured.

The later [authenticated network-response smoke](CODEX_NETWORK_RECEIPT_SMOKE.md) tests a different gap. Tablaze's opt-in response journal, Harness MCP, and Browser Use CLI-MCP each passed once using native Codex; structured MCP direct tools did not submit before the deadline. Two separately configured nested-Agent attempts also had no successful write. Browser Use's programmable CLI entry passed, so this result is specific to the entry points and attempts. It does not demonstrate general script/CDP parity, CSV handling, or product-wide superiority.

The objective remains stronger overall functionality than Browser Use. A result against Python Agent alone cannot establish that objective. Local agents, tools for an existing agent, and managed services need separate measurements, with unresolved tracks retained in the final claim.

Python/JS program execution can access the host and network. That flexibility is a functional surface, not a sandbox guarantee. Similarly, storing cookies or a transcript is not proof that resumed actions use the intended account/tenant.

Cloud V4 currently defaults to `gpt-5.6-luna`. Its documented `gpt-6-astra` reasoning values stop at `max` and default to `xhigh`; **`ultra` is not an accepted V4 value in this documentation**. A later Cloud comparison needs an explicitly common supported setting and a new report, not a silent mapping from the existing Codex `ultra` experiments. V4 structured output is documented as JSON requested in the task and validated by the application. [Models](https://docs.browser-use.com/cloud/agent/models), [reasoning settings](https://docs.browser-use.com/cloud/agent/thinking-levels), [structured output](https://docs.browser-use.com/cloud/agent/structured-output).

## Five substantive gaps to close or measure

These concern the current Tablaze development interfaces, not its older published eight-tool starting point. “Unmeasured” is not “unsupported.”

1. **Programmable browser and network workflows.** Harness exposes JS, CDP and HTTP; Pi combines these with a persistent worker and files. Tablaze now has typed trusted custom handlers, an [optional owned-tab response journal](NETWORK.md), and [opt-in page-origin JavaScript](PAGE_SCRIPT.md). The new script tool has full page-origin authority but no host execution, raw CDP, persistent JS globals, or Pi-style worker/files. A real-Chrome fixture confirms a write followed by an ambiguous script error; the [one-attempt native Codex smoke](CODEX_PAGE_SCRIPT_SMOKE.md) shows both Tablaze script and Browser Use CLI-MCP passing the same authenticated-response judge once. Neither covers a checked artifact or establishes comparable workflow breadth. Sources: Harness MCP and Pi primitives above.

2. **Whole-browser domain policy and scoped secret insertion.** Pi implements optional document interception for redirects, frames and related popups, plus named secrets checked against the actual input document. Tablaze custom-tool `allowedOrigins`/tenant binding is useful but is not a global browser navigation policy or a general named-secret fill API. Test an allowed page that redirects or opens a forbidden frame/popup; the denied endpoint must record no forbidden document request, and secret values must not enter model text/logs. Pi explicitly excludes subresources, arbitrary Node/network access and independent CDP connections from its navigation boundary; do not claim a network firewall for either system. [Pi policy source](https://github.com/browser-use/browser-use-pi/blob/fa838f3298673950923bdaf12bd3c1b6279cd119/src/policy.ts).

3. **Long-task control and deliverable contracts.** Pi has typed final output, `validateResult`, pause/execute/resume/steer, explicit partial artifacts, model-based compaction and a soft cost cap. Its API documents that intermediate published values are not validated against the final schema. Tablaze has bounded steps/calls/history, optional deterministic history pruning, cancellation, completion evidence, checkpoints, an optional draft-7 JSON final-output contract, and independent schema-bound checked partials with application validation. The partial ledger survives time/step limits in a trusted local checkpoint and report; it is not a separate file artifact and does not mark the overall task complete. SDK pause/steer and these output mechanisms have not been tested against Pi in a matched task. Pi also supports same-worker `execute(code)` while paused; Tablaze has no persistent JS worker or cost cap. A long paginated extraction should preserve checked partial rows on a time/cost boundary, accept intervention, finish with schema-valid data, and never duplicate a committed write after recovery. Account separately for summary calls and unpriced/unknown usage; Pi's cost cap can overshoot one response. [API](https://github.com/browser-use/browser-use-pi/blob/fa838f3298673950923bdaf12bd3c1b6279cd119/docs/api.md), [runtime](https://github.com/browser-use/browser-use-pi/blob/fa838f3298673950923bdaf12bd3c1b6279cd119/src/agent.ts).

4. **Managed local profile lifecycle and resumed identity.** Pi exposes owned persistent profile directories with concurrent-owner rejection; existing Chrome and cloud profiles have different ownership. Tablaze now has an opt-in [owned profile mode](PROFILES.md) with an exclusive lock, a directory marker and a required profile ID on reuse. A real-Chrome mechanism test restarts the Tablaze process, preserves a durable cookie, localStorage and IndexedDB, rejects a busy or mismatched profile before a write URL, and isolates two profiles at the same origin. This does not prove production authentication or wrong-tenant-write prevention after the account changes **inside the same profile**. Its workspace restore still omits DOM/form drafts/sessionStorage and cannot be combined with a persistent profile. A held-out authenticated popup-return comparison, same-origin account switch, and model-driven recovery are still needed. Do not credit Pi with Tablaze-style tenant binding merely because it has profiles. [Pi sessions](https://github.com/browser-use/browser-use-pi/blob/fa838f3298673950923bdaf12bd3c1b6279cd119/docs/sessions.md), local `src/browser.ts`/`src/cli.ts`/`src/custom-tools.ts`.

5. **Managed operation and observability.** Cloud supplies browser provisioning, proxy/stealth/CAPTCHA facilities, managed profiles/workspaces, live preview and optional recording. Pi and Harness also expose local recording; Pi exports captured frames without rerunning effects. Tablaze's run trace, screenshots and demo recorder do not establish this full service/recording surface. Keep a service track for provisioning/teardown, parallel isolated runs, file retrieval, interruption and human intervention; verify no owned browser remains billed/running after cleanup. Cloud access is currently **not_run**, not absent or passed. [Cloud browser](https://docs.browser-use.com/cloud/browser/quickstart), [Pi sessions/recording](https://github.com/browser-use/browser-use-pi/blob/fa838f3298673950923bdaf12bd3c1b6279cd119/docs/sessions.md).

## Next mandatory tool-track: retain the actual Codex agent

Use **native `codex exec` with configured MCP servers**, retaining its own multi-round model/tool loop. Keep the same Codex binary/version, `gpt-6-astra`, reasoning level, HTTP provider configuration, prompt, budgets, fixture, browser build and image access across arms. `--json` records events; it does not replace the agent with a single JSON decision. `--output-schema`, if used, constrains the final report, not every intermediate tool call. Codex documents MCP calls in JSONL and persisted-session resume. [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [MCP configuration](https://learn.chatgpt.com/docs/extend/mcp).

Do **not** reuse `bench/comparison/codex-transport.mjs` as the external tool-track agent. That bridge deliberately accepts only inference/reasoning/message events, rejects external tool items, disables local image viewing, and lets Tablaze/Python Agent execute their own plans. It is appropriate to the existing agent track, not this new track.

The next adapter should start the following **installed, pinned** commands as stdio children. Replace placeholder paths, `PORT`, and `ATTEMPT_ID` with the experiment's actual values. Tablaze starts its stdio server with no subcommand; `stdio` is an internal mode name, not a CLI argument. These are source-checked entry points, not a claim that an end-to-end Codex/MCP attempt was run during this audit.

### Preflight and acceptance before calling a model

1. Verify versions and source/build/dependency hashes. MCP initialize → tools/list → browser observation → second stateful call must work. Capture advertised schemas, instructions and error shape. Missing binaries, unsupported MCP versions or credentials are `not_run`; a source claim alone cannot pass this check.
2. Prove screenshot delivery. Tablaze and BU MCP return image blocks; Harness MCP needs the same enabled Codex `view_image` tool available in both arms, with its screenshot directory readable. If a pure image-transport adapter is used instead, identify/hash it and retain a native run as a separate variant. Never place base64 screenshot text in the prompt and call that equivalent visual input.
3. Use owned resettable browser fixtures, scoped daemon directories and explicit endpoint selection. Verify tab ownership, server restart/reconnection, cancellation and bounded process-group/daemon cleanup. MCP server exit does not imply Harness daemon exit. Preserve the external browser owner until the judge/artifact collection completes.
4. For `--mcp`, first measure the external-agent-only configuration with extraction/nested `retry_with_browser_use_agent` disabled and **label that restriction**. Then retain a separate full-capability variant with all nested-model requests routed to the same configured model and included in usage/latency. Do not use the restricted variant to claim superiority over the complete product.
5. Run the existing independent business judges without exposing them to the agent, then add the discriminating scenarios above. Report business pass, agent completion and whole-run return/cleanup separately; include all failed attempts and unknown usage. Preserve the full comparison contract's held-out tasks, repeats and uncertainty requirements.

For a recovery experiment, use a recorded Codex session ID and explicit `codex exec resume <ID>` rather than `--last`; do not use `--ephemeral` when persistence is required. Codex transcript continuation alone does not recreate an MCP process, JS/Python globals, browser login or tenant identity. Reattach only the experiment's owned endpoint, re-observe, and reconcile ambiguous writes before issuing another mutation.

Pi belongs in the **full-agent** track: its public `models`/`streamFn` extension can use a common provider transport without replacing its Pi runtime. A Codex inference adapter would need faithful text/tool/image conversion and actual usage/error handling; this has not been implemented or measured. Cloud Browser can later supply a common remote CDP backend; Cloud Agent is a separate hosted-agent comparison and must not be represented as the unchanged Codex agent. [Pi model integration](https://github.com/browser-use/browser-use-pi/blob/fa838f3298673950923bdaf12bd3c1b6279cd119/docs/models.md).
