# Development status — 2026-09-24

The active objective remains **Tablaze functionality exceeding Browser Use**. It is not complete. Current source adds browser workflows, a task runner, recovery, extraction, typed custom tools and an executable comparison harness. The evidence below does not establish full parity or superiority.

当前目标仍是功能超过 Browser Use，尚未完成。功能回归、模型驱动任务和整体竞争力的验收分别记录。

## Implemented

- **16 MCP tools:** original observation/actions/verification plus bounded text finding through virtual lists, navigation/history, owned tabs/popups, downloads, native dialog decisions, state export/import, schema extraction and PDF export.
- **Opt-in direct task URL:** `runAgent({ directOpenTaskUrl: true })` and CLI `--direct-open-task-url` use the checkpointed initializer when the trusted task has one valid HTTP(S) URL without embedded credentials. The first planner call receives the page snapshot. Multi-URL tasks fall back to model planning, explicit `startUrl` takes precedence, and attempted navigation is never replayed on resume. The default remains off.
- **Model-facing check scopes:** the Agent instructions and actual MCP `tab_act`/`tab_verify` schemas now explain that `text` excludes input/textarea/select values and `value` reads them. This targets the repeated iframe input-as-text mistakes in the [direct-task-URL comparison](CODEX_DIRECT_TASK_URL_20260924.md) without changing verification results or dropping requested checks. The effect on real-model decisions remains to be measured.
- **Optional page-origin scripts:** `--page-script` adds a model-facing `tab_script` tool for JSON-in/JSON-out JavaScript in an owned main document. It consumes the current snapshot, returns a fresh one, invalidates browser bindings and marks uncertain post-execution failures for reconciliation. It has full page-origin authority and is incompatible with configured secrets, external CDP and navigation policy. This is neither host execution nor a persistent JS/CDP worker. See [page-script contract](PAGE_SCRIPT.md).
- **Optional network response journal:** `--capture-network` adds a seventeenth MCP tool for bounded response metadata and small declared text bodies from owned tabs and popups. A real-Chrome fixture verifies an authenticated popup receipt and exclusion of unrelated CDP tabs. It is not arbitrary JS/CDP execution or a matched Browser Use result. See [network contract](NETWORK.md).
- **Optional real browser video:** `--record-video` saves private WebM for each owned tab in an isolated context, with finalized path, size and SHA-256 surfaced by `tab_close` or the standalone run report. Missing output is an error. It does not capture audio or draw a synthetic cursor and cannot be used with CDP or a persistent profile. Configured secrets require explicit sensitive-artifact permission. See [recording contract](RECORDING.md).
- **Optional HAR and Playwright trace:** `--record-har` captures full network metadata without response bodies; `--record-trace` captures browser actions, DOM snapshots and screenshots in a ZIP. Both require owned isolated contexts, return private finalized paths, sizes and SHA-256 after close/dispose, and refuse configured secrets without explicit sensitive-artifact permission. They are debugging files, not proof of task completion. See [diagnostic contract](DIAGNOSTICS.md).
- **Trusted browser configuration:** custom viewport, device pixel ratio and page permissions are available through CLI/SDK/MCP server launch for owned isolated contexts and persistent profiles. External CDP contexts reject these settings. A real-Chrome test checks the actual viewport, ratio and geolocation permission. See [configuration and limits](BROWSER_CONFIGURATION.md).
- **Mobile and region emulation:** trusted CLI/SDK settings add screen size, user agent, locale, time zone, mobile viewport behavior and touch to owned isolated contexts and persistent profiles. A real-Chrome page check verifies observable browser values. There is no bundled cohesive device preset or claim of full fingerprint emulation; external CDP contexts reject these settings. See [configuration and limits](BROWSER_CONFIGURATION.md).
- **Opt-in owned-context proxy:** a trusted HTTP(S)/SOCKS5 proxy setting is passed to Playwright; the CLI reads an optional password from a named environment variable and omits proxy credentials from doctor output. A real-Chrome test proves an HTTP request to a synthetic hostname reached a local proxy. Authentication, bypass and SOCKS5 transport are not yet independently tested. See [configuration and limits](BROWSER_CONFIGURATION.md).
- **Owned persistent Chrome profile:** `--profile-dir` starts a dedicated private local profile. Its marker and exclusive lock reject unrelated/busy directories; reusing it requires an operator-supplied profile ID. SDK, stdio MCP and a separate Tablaze process were exercised with real Chrome; a durable cookie, localStorage and IndexedDB survived restart. This persists browser-managed state, not Agent progress or active tenant identity. External CDP, state/workspace import, CLI checkpoint/resume and document navigation policy are incompatible. See [profile contract](PROFILES.md).
- **Complex pages:** scoped/viewport snapshots, shared composed DOM traversal across open shadow roots and slots, selected frames, horizontal/vertical container scrolling, labeled drag targets, hover/double-click, coordinate actions and screenshot coordinate metadata.
- **Initial iframe readiness and selection:** a bounded 800 ms wait allows newly attached child frames to leave empty/about:blank URLs. If the main page has no actionable controls and exactly one visible child frame has a form field, `tab_open` returns that child's actionable snapshot and a bounded parent-text summary. Real-Chrome checks cover direct fill/click from the first result and ambiguous, hidden, button-only and main-control fallbacks. A [six-pair Codex follow-up](CODEX_IFRAME_DIRECT_OPEN_SMOKE.md) confirms direct use on one iframe fixture, while broader speed remains unproven.
- **Action-frame feedback:** `tab_act` identifies the frame used by its action batch. If optional post-checks fail and a follow-up snapshot is requested, the MCP result observes that same frame, falling back to the main document if it disappeared. A real-Chrome regression reproduces the input-as-text check failure from two model traces and verifies the result includes the child form and saved status without replaying the write. Model-level latency on this newer source is not yet measured.
- **Form-state visibility without credential disclosure:** password controls expose a filled/empty boolean while retaining value redaction; visible disabled selects retain their live value and selected option. A real-Chrome regression checks both states and a post-fill diff. The [current Browser Use issue audit](BROWSER_USE_2026_AUDIT.md) separates these narrow fixes from unresolved product gaps.
- **Owned popup timing and executed-only stall detection:** observed `target="_blank"` links advertise that they open a new tab; their clicks wait briefly for the owned popup event before the action returns in stay mode. A deterministic Agent test confirms five proposed but skipped writes neither dispatch nor cause a false stall warning. The [full Node 24 + Chrome run](evidence/development-tests-loop-popup-node24.txt) passed 491/491; matched real-model popup and long-task measurements remain open.
- **Visual first observation:** `tab_open` now includes a viewport JPEG and CSS-pixel coordinates when its main-frame snapshot sees an in-viewport canvas but no actionable controls. The MCP test confirms usable image bytes, a real canvas click accepted by the independent fixture server, no automatic image for a form, and cancellation cleanup that preserves a sibling session. The [complete Node 24 + Chrome log](evidence/development-tests-initial-vision-node24.txt) passed 493/493.
- The [fresh four-pair canvas Codex comparison](CODEX_CANVAS_INITIAL_VISION_SMOKE.md) on clean commit `07a362d` shows Tablaze 4/4 and Browser Use 3/4 independent business passes; Browser Use's fourth attempt clicked twice yet reported Agent success. All four Tablaze traces used the initial `tab_open` image and skipped `tab_capture`, with one write each. On the three jointly successful seeds, median whole-run time was 41.552 versus 61.113 s and Agent-done time 41.401 versus 42.578 s, with Browser Use's default judge included only in whole-run time. This one visible task does not establish production speed or overall superiority.
- **File and state workflows:** visible-input/hidden-chooser uploads, actual download artifacts, private PDFs with source/digest, isolated cookies/localStorage/IndexedDB restoration, owned tab URLs and active-tab reconstruction.
- **Trusted file and authentication-state policy:** CLI Agent and stdio MCP deny host uploads by default; repeatable `--available-file` grants exact files through model-visible aliases, and completed downloads can be reused only inside their owning session. Model-supplied storage-state paths remain limited to this engine's exports. A trusted `--storage-state-file` instead captures an existing Playwright auth-state JSON before the model starts and initializes new isolated sessions without exposing its path. Both policies bind workspace restoration. See [file policy](FILE_POLICY.md).
- **Structured extraction:** draft-7 JSON schema validation and typed DOM fields with source citations; a provider-neutral multi-source extraction API requires exact source quotes and per-leaf coverage. Quote presence does not itself prove semantic support; applications can require their own support validator.
- **Separate extraction model in Agent tasks:** `tablaze run --extraction-model` adds `tab_extract_model`, which reads the active browser frame through `tab_extract`, rejects incomplete text, and returns schema-validated data with exact-quote citations from a separately selected model. The full [Node 24 + Chrome regression](evidence/development-tests-agent-extraction-node24.txt) passed 524/524 tests, including real-browser Agent and spawned CLI workflows. These are scripted extraction-model checks, not broad live-model quality or Browser Use speed measurements.
- **Agent execution:** provider-neutral planner, real MCP transport, images, sequential feedback, explicit verification evidence, task-specific acceptance, cancellation and cumulative budgets. An optional draft-7 final-output contract requires schema-valid JSON data before completion. An independent optional partial-output contract accepts checked, append-only units and retains them on incomplete outcomes; shape validation alone cannot prove the task's business outcome. In-process SDK control can pause at a safe boundary, accept trusted steering, and replan without replaying queued writes. See [Agent runner](AGENT.md).
- **Provider entry points:** SDK factories and CLI selection for Codex, native Anthropic Messages, native Ollama chat and compatible HTTP. Models stay explicit; protocol-specific authentication, tool/image mapping and real usage counters are documented in [provider contracts](PROVIDERS.md). Codex has explicit process/file cleanup and fixed diagnostics; the CLI drains its final reported usage before output. This implementation does not imply live validation of every provider/model.
- **Typed custom tools:** the SDK's `defineTool` and `createToolRegistry` validate Zod input/output contracts, expose JSON Schema to planners, and supply trusted application context outside model arguments. Exact-origin availability is refreshed per decision; trusted read/write effects and unknown write outcomes control recovery. Custom handlers do not replace browser verification or the application acceptance policy. See [custom-tool contracts](CUSTOM_TOOLS.md).
- **Execution context continuity:** browser guards check the main document, navigation and tab-activation history. Private `contextKey` changes invalidate old observations and verification across planning catalogs, including switching away and back. Confirmed closure of an already-verified session preserves verify–close–finish; any subsequent mutation still invalidates that evidence.
- **Failure diagnostics:** unrecovered planner, catalog, application-hook and persistence failures expose fixed codes and safe metadata through the Agent result and CLI. Original exceptions and provider bodies are omitted; retry eligibility is reported without adding automatic retries.
- **Initial navigation and popup continuity:** explicit caller-supplied start URLs run before planning through the normal dispatcher; checkpoint v5 retains initialization tracking and prevents automatic replay. Optional `follow-single` popup policy returns a fresh observation and stops queued old-context operations; workspace restoration retains that policy.
- **Optional navigation policy:** trusted CLI/SDK exact-origin allow/deny rules check HTTP(S) document requests across redirects, frames and popups in owned isolated browsers. External CDP is unsupported; workspace restoration requires the same policy hash. Non-document traffic is unrestricted, and transport loss cannot guarantee atomic fail-closed behavior. This is not a network firewall. See [configuration and observed limits](NAVIGATION_POLICY.md).
- **Opening and shutdown:** cancellation tracks resources arriving after the caller stops waiting. Disposal has a bounded result and explicitly reports incomplete cleanup; unresolved external CDP creation can retain a connection for late owned-page cleanup without closing unrelated pages.
- **Verification efficiency:** observed form values can be checked by ref without inferred selectors; document/node guards and a final value reread revoke outdated evidence. Optional `tab_act.post_checks` uses those same checks after a complete action batch, allowing one model decision to act and verify an expected same-document outcome. Failed checks require replanning and cannot become completion evidence; completed actions are never replayed automatically. Agent guidance reuses current action snapshots. Model requests omit exact duplicate MCP text while preserving complete audit records.
- **Delayed controls in one batch:** after an observed activating action, `tab_act.click_named` can wait for one visible button or menu item with an exact accessible name in the same document. Missing, ambiguous, replaced and navigated targets stop before further input, preserving prior action receipts. Existing controls still use observed refs; a successful click still requires business-outcome verification. The [matched development study](CODEX_DELAYED_TARGET_SMOKE.md) preserves the initial wrong-role failure and the corrected real-model adoption.
- **Long-task recovery:** version-5 checkpoints bind registered tool contracts, trusted principal/tenant/policy identity and configured final/partial schema digests, with strict migration of valid version-1/2/3/4 files. Checked partials retain their publication-time verification snapshots and matching history notes across limits and resume; new publications still require fresh verification. Changed identities or contracts cannot be waived by reconciliation. Private atomic CLI persistence, fresh-observation/verification gates, system-policy inheritance, required acceptance-hook continuity, planner-only retries/fallback, deterministic history compaction and stall feedback remain supported. Uncertain mutations require explicit reconciliation and are never automatically replayed; bound custom-tool runs resume through the SDK that reconstructs their handlers.
- **Comparison infrastructure:** 16 development tasks with server/file judges, isolated resets, source/dist/task/judge hashes, pinned Browser Use adapter, HTTP or shared Codex CLI inference, measured usage and bounded process cleanup. The newest task checks an authenticated network response after a synthetic cross-origin authorization popup. Reports distinguish independent business acceptance, observed Agent completion and deadline-bounded full return; default Browser Use judging is retained and measured separately. Scripted and real-model attempts remain separately labeled.
- **Codex terminal handling:** the bridge keeps generic error notifications as diagnostics and waits for the same process's terminal outcome. A valid response also requires a completed turn and successful process exit; timeout, cancellation and external-tool interception remain enforced. The production Codex planner now makes at most one extra inference call to repair malformed JSON-encoded function arguments before any tool dispatch, counting both calls' reported usage. Fixed validation-stage diagnostics expose the boundary without raw response text. Historical failures are retained unchanged.

## Remaining work toward the full goal

The capability and evaluation contract is in [Browser Use comparison](BROWSER_USE_COMPARISON.md), supplemented by the [Agent/MCP/Harness/Pi/cloud variants audit](BROWSER_USE_VARIANTS.md). The audit identifies distinct comparison tracks rather than a measured whole-product ranking. Current gaps include:

1. Broader unknown long-running tasks, virtualized and authenticated applications, production authorization/popup return flows and repeated recovery under real models.
2. Broader service/model coverage and live validation of the new provider integrations, durable run/usage aggregation, configurable policies, trace analysis and replay debugging.
3. Broader advanced-site extensions and real-model evaluation of custom-tool workflows. Typed registration, exact-origin filtering, trusted application context and recovery binding are implemented; this does not establish extensibility parity across Browser Use's broader ecosystem.
4. Broader network and file-access limits, scoped secret handling and full persistent-profile/tenant behavior. The owned profile now persists durable browser storage across a process restart, but same-origin account switching, production login and model-driven resume are unverified. The exact-origin document-navigation policy addresses only part of permissions and is unavailable with persistent profiles; it does not restrict subresource traffic or provide a network firewall.
5. A frozen broader task set, matched repeated runs, failure analysis and uncertainty reporting. Small smoke results cannot establish a cross-product win.
6. Broader platform verification for the expanded release and appropriate distribution; the current macOS clean-install check has passed.
7. Execute the additional official MCP, Harness, Pi and cloud comparison tracks under disclosed controls before any product-wide superiority claim.
