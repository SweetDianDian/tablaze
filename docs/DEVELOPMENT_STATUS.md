# Development status — 2026-09-22

The active objective remains **Tablaze functionality exceeding Browser Use**. It is not complete. Current source adds browser workflows, a task runner, recovery, extraction, typed custom tools and an executable comparison harness. The evidence below does not establish full parity or superiority.

当前目标仍是功能超过 Browser Use，尚未完成。功能回归、模型驱动任务和整体竞争力的验收分别记录。

## Implemented

- **15 MCP tools:** original observation/actions/verification plus navigation/history, owned tabs/popups, downloads, native dialog decisions, state export/import, schema extraction and PDF export.
- **Complex pages:** scoped/viewport snapshots, shared composed DOM traversal across open shadow roots and slots, selected frames, horizontal/vertical container scrolling, labeled drag targets, hover/double-click, coordinate actions and screenshot coordinate metadata.
- **File and state workflows:** visible-input/hidden-chooser uploads, actual download artifacts, private PDFs with source/digest, isolated cookies/localStorage/IndexedDB restoration, owned tab URLs and active-tab reconstruction.
- **Structured extraction:** draft-7 JSON schema validation and typed DOM fields with source citations; a provider-neutral multi-source extraction API requires exact source quotes and per-leaf coverage. Quote presence does not itself prove semantic support; applications can require their own support validator.
- **Agent execution:** provider-neutral planner, real MCP transport, configurable model endpoint, images, sequential feedback, explicit verification evidence, task-specific acceptance, cancellation and cumulative budgets.
- **Typed custom tools:** the SDK's `defineTool` and `createToolRegistry` validate Zod input/output contracts, expose JSON Schema to planners, and supply trusted application context outside model arguments. Exact-origin availability is refreshed per decision; trusted read/write effects and unknown write outcomes control recovery. Custom handlers do not replace browser verification or the application acceptance policy. See [custom-tool contracts](CUSTOM_TOOLS.md).
- **Execution context continuity:** browser guards check the main document, navigation and tab-activation history. Private `contextKey` changes invalidate old observations and verification across planning catalogs, including switching away and back. Confirmed closure of an already-verified session preserves verify–close–finish; any subsequent mutation still invalidates that evidence.
- **Failure diagnostics:** unrecovered planner, catalog, application-hook and persistence failures expose fixed codes and safe metadata through the Agent result and CLI. Original exceptions and provider bodies are omitted; retry eligibility is reported without adding automatic retries.
- **Initial navigation and popup continuity:** explicit caller-supplied start URLs run before planning through the normal dispatcher; checkpoint v3 retains initialization tracking and prevents automatic replay. Optional `follow-single` popup policy returns a fresh observation and stops queued old-context operations; workspace restoration retains that policy.
- **Opening and shutdown:** cancellation tracks resources arriving after the caller stops waiting. Disposal has a bounded result and explicitly reports incomplete cleanup; unresolved external CDP creation can retain a connection for late owned-page cleanup without closing unrelated pages.
- **Verification efficiency:** observed form values can be checked by ref without inferred selectors; document/node guards and a final value reread revoke outdated evidence. Agent guidance reuses current action snapshots. Model requests omit exact duplicate MCP text while preserving complete audit records.
- **Long-task recovery:** version-3 checkpoints bind registered tool contracts and trusted principal/tenant/policy identity, with strict unbound migration of valid version-1/2 files. Changed identities or contracts cannot be waived by reconciliation. Private atomic CLI persistence, fresh-observation/verification gates, system-policy inheritance, required acceptance-hook continuity, planner-only retries/fallback, deterministic history compaction and stall feedback remain supported. Uncertain mutations require explicit reconciliation and are never automatically replayed; bound custom-tool runs resume through the SDK that reconstructs their handlers.
- **Comparison infrastructure:** 13 development tasks with server/file judges, isolated resets, source/dist/task/judge hashes, pinned Browser Use adapter, HTTP or shared Codex CLI inference, measured usage and bounded process cleanup. Reports distinguish independent business acceptance, observed Agent completion and deadline-bounded full return; default Browser Use judging is retained and measured separately. Scripted and real-model attempts remain separately labeled.
- **Codex terminal handling:** the bridge keeps generic error notifications as diagnostics and waits for the same process's terminal outcome. A valid response now also requires a completed turn and successful process exit; timeout, cancellation and external-tool interception remain enforced. Historical failures are retained unchanged.

## Verification and limits

`TABLAZE_BROWSER_CHANNEL=chrome npm test`: **264 passed, 0 failed, 0 skipped, 0 cancelled**; exit 0, duration 133,081.4225 ms. The [validation manifest](evidence/development-validation.json) records exact source hashes and environment. The [raw test log](evidence/development-tests.txt) includes local real-Chrome, MCP, cross-process CLI, extraction, lifecycle, drag, ref-verification races, typed custom-tool/context recovery and model-transport regressions. Scripted model responses and fake process tests validate mechanisms, not general model ability.

Real Codex inference uses the existing CLI-managed ChatGPT login. The first Tablaze form smoke passed independent server-side judging: one correct submission, zero duplicate writes, five model calls and four tool calls. It reported 76,451 input tokens and 973 output tokens, taking 102.268 seconds. These include Codex CLI prompt overhead; they are not raw-model API cost or evidence of superior speed. Its full report is retained locally at `artifacts/comparison/codex-tablaze-form-v1/results.json`.

All real-model runs described below, including the terminal-handling follow-up, used runtimes from before the typed custom-tool SDK and bound checkpoint/context-key implementation. Their raw reports and recorded source hashes remain unchanged. Local scripted-planner, MCP, backend and Chrome regressions exercise the new mechanisms; those historical model results do not measure their planning quality, latency or task success rate.

The matched smoke uses pinned Browser Use 0.13.10 commit `d8110c5ff87ccba887aaa726cdb780f2f84bef8d`, Codex CLI 0.155.0-alpha.9.2, model `gpt-6-astra`, reasoning effort `ultra`, Chrome 153.0.8010.53 and a 1280×800 viewport. The Codex bridge preserves each framework's agent/tool execution but adds the same CLI inference wrapper. Temperature/output-token control is not verified for this CLI bridge; tool-call limits differ between frameworks. Such limitations prevent treating a small smoke sample as a superiority experiment.

The earlier five-round local engine benchmark is retained as [historical increment evidence](../bench/results/2026-09-22T08-07-04.785Z.json): cold open 498.498 ms, warm snapshot 4.236 ms, four-action batch 228.515 ms and verification 9.016 ms (medians). It predates the latest additions and excludes model/transport/internet time. It is not a competitor comparison or a new performance regression measurement.

Storage restoration does not restore live DOM, form drafts, sessionStorage, extensions, browser history or interrupted downloads. DOM guards cannot make webpage scripts atomic. PDF export requires Chromium printing support. Extraction source URLs must be HTTP(S); closed shadow roots remain outside DOM observation. Authentication state and full checkpoints contain sensitive data even with file mode 0600.

npm publication remains pending. Historical Linux/Node 20/22 release evidence covers its recorded earlier archive, not all current additions. Package version remains 0.1.0 pending release preparation.

The first [matched Codex smoke](CODEX_COMPARISON_RESULTS.md) is complete: normal Agent completion plus independent business acceptance was Tablaze 1/2 and Browser Use 2/2. Both reached the intended business state twice, but Tablaze hit the form deadline before final completion and took more time/tokens in both tasks. This exposes work to do; it does not establish a general ranking.

The [second Codex smoke](CODEX_COMPARISON_RESULTS_V2.md) follows the ref-verification and request-deduplication changes. Both engines reached and reported both business outcomes without duplicate writes. Tablaze returned normally twice (form 68.936 s, popup 111.528 s). Browser Use returned normally on the form (58.909 s), and reached `done(success=True)` on the popup before its default post-task judge caused the whole run to exceed the deadline (181.831 s including cleanup). Its raw adapter status remains failed, but this is not an unperformed approval. Browser Use model-call counts include judging, and cancelled-call usage was absent. These phase and policy differences are documented rather than reclassified into a superiority claim.

The [third Codex smoke](CODEX_COMPARISON_RESULTS_V3.md) expands to five tasks with explicit initialization and popup following. Independent business acceptance was 5/5 on each side; successful Agent completion was Tablaze 4/5 and Browser Use 5/5. Both produced matching downloaded files and avoided duplicate writes. Tablaze's duplicate-write run observed the correct receipt, then its third Codex request emitted an error event and the old bridge terminated the process. The underlying message and that call's usage were not retained; the failure remains in the result. On jointly completed tasks, whole-run timing favored Tablaze for form/popup and Browser Use for iframe/download, while Browser Use reported completion earlier on all four before its default judge. These observations do not establish overall superiority.

The independent [terminal-handling follow-up](CODEX_TERMINAL_FOLLOWUP.md) reran only the duplicate-write task after the bridge and diagnostic fixes. Both engines completed successfully with one write and no duplicates: Tablaze 59.415 s, Browser Use 93.706 s including its default judge. Browser Use's first planning request emitted a generic error notification and then completed normally in the same process, directly exercising the shared bridge fix. Its underlying error category remains unknown. This fresh pair does not replace the third-round failure or establish general superiority.

## Remaining work toward the full goal

The complete capability and evaluation contract is in [Browser Use comparison](BROWSER_USE_COMPARISON.md). Current gaps include:

1. Broader unknown long-running tasks, virtualized applications, authentication/popup return flows and repeated recovery under real models.
2. Direct provider integrations, durable run/usage aggregation, configurable policies and trace/replay debugging.
3. Broader advanced-site extensions and real-model evaluation of custom-tool workflows. Typed registration, exact-origin filtering, trusted application context and recovery binding are implemented; this does not establish extensibility parity across Browser Use's broader ecosystem.
4. Configurable network/domain/file limits and full persistent-profile behavior.
5. A frozen broader task set, matched repeated runs, failure analysis and uncertainty reporting. Small smoke results cannot establish a cross-product win.
6. Broader platform verification for the expanded release and appropriate distribution; the current macOS clean-install check has passed.
7. Resolve official variant/cloud-service scope before any product-wide superiority claim.
