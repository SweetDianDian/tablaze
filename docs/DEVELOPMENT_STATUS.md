# Development status — 2026-09-23

The active objective remains **Tablaze functionality exceeding Browser Use**. It is not complete. Current source adds browser workflows, a task runner, recovery, extraction, typed custom tools and an executable comparison harness. The evidence below does not establish full parity or superiority.

当前目标仍是功能超过 Browser Use，尚未完成。功能回归、模型驱动任务和整体竞争力的验收分别记录。

## Implemented

- **16 MCP tools:** original observation/actions/verification plus bounded text finding through virtual lists, navigation/history, owned tabs/popups, downloads, native dialog decisions, state export/import, schema extraction and PDF export.
- **Optional action marker:** visual target indicator is off by default in real sessions and can be enabled for a headed walkthrough or recording. Input and scrolling show a target ring; a mouse icon appears only for pointer operations. It does not represent the physical mouse trajectory.
- **Optional page-origin scripts:** `--page-script` adds a model-facing `tab_script` tool for JSON-in/JSON-out JavaScript in an owned main document. It consumes the current snapshot, returns a fresh one, invalidates browser bindings and marks uncertain post-execution failures for reconciliation. It has full page-origin authority and is incompatible with configured secrets, external CDP and navigation policy. This is neither host execution nor a persistent JS/CDP worker. See [page-script contract](PAGE_SCRIPT.md).
- **Optional network response journal:** `--capture-network` adds a seventeenth MCP tool for bounded response metadata and small declared text bodies from owned tabs and popups. A real-Chrome fixture verifies an authenticated popup receipt and exclusion of unrelated CDP tabs. It is not arbitrary JS/CDP execution or a matched Browser Use result. See [network contract](NETWORK.md).
- **Owned persistent Chrome profile:** `--profile-dir` starts a dedicated private local profile. Its marker and exclusive lock reject unrelated/busy directories; reusing it requires an operator-supplied profile ID. SDK, stdio MCP and a separate Tablaze process were exercised with real Chrome; a durable cookie, localStorage and IndexedDB survived restart. This persists browser-managed state, not Agent progress or active tenant identity. External CDP, state/workspace import, CLI checkpoint/resume and document navigation policy are incompatible. See [profile contract](PROFILES.md).
- **Complex pages:** scoped/viewport snapshots, shared composed DOM traversal across open shadow roots and slots, selected frames, horizontal/vertical container scrolling, labeled drag targets, hover/double-click, coordinate actions and screenshot coordinate metadata.
- **File and state workflows:** visible-input/hidden-chooser uploads, actual download artifacts, private PDFs with source/digest, isolated cookies/localStorage/IndexedDB restoration, owned tab URLs and active-tab reconstruction.
- **Structured extraction:** draft-7 JSON schema validation and typed DOM fields with source citations; a provider-neutral multi-source extraction API requires exact source quotes and per-leaf coverage. Quote presence does not itself prove semantic support; applications can require their own support validator.
- **Agent execution:** provider-neutral planner, real MCP transport, images, sequential feedback, explicit verification evidence, task-specific acceptance, cancellation and cumulative budgets.
- **Provider entry points:** SDK factories and CLI selection for Codex, native Anthropic Messages, native Ollama chat and compatible HTTP. Models stay explicit; protocol-specific authentication, tool/image mapping and real usage counters are documented in [provider contracts](PROVIDERS.md). Codex has explicit process/file cleanup and fixed diagnostics; the CLI drains its final reported usage before output. This implementation does not imply live validation of every provider/model.
- **Typed custom tools:** the SDK's `defineTool` and `createToolRegistry` validate Zod input/output contracts, expose JSON Schema to planners, and supply trusted application context outside model arguments. Exact-origin availability is refreshed per decision; trusted read/write effects and unknown write outcomes control recovery. Custom handlers do not replace browser verification or the application acceptance policy. See [custom-tool contracts](CUSTOM_TOOLS.md).
- **Execution context continuity:** browser guards check the main document, navigation and tab-activation history. Private `contextKey` changes invalidate old observations and verification across planning catalogs, including switching away and back. Confirmed closure of an already-verified session preserves verify–close–finish; any subsequent mutation still invalidates that evidence.
- **Failure diagnostics:** unrecovered planner, catalog, application-hook and persistence failures expose fixed codes and safe metadata through the Agent result and CLI. Original exceptions and provider bodies are omitted; retry eligibility is reported without adding automatic retries.
- **Initial navigation and popup continuity:** explicit caller-supplied start URLs run before planning through the normal dispatcher; checkpoint v3 retains initialization tracking and prevents automatic replay. Optional `follow-single` popup policy returns a fresh observation and stops queued old-context operations; workspace restoration retains that policy.
- **Optional navigation policy:** trusted CLI/SDK exact-origin allow/deny rules check HTTP(S) document requests across redirects, frames and popups in owned isolated browsers. External CDP is unsupported; workspace restoration requires the same policy hash. Non-document traffic is unrestricted, and transport loss cannot guarantee atomic fail-closed behavior. This is not a network firewall. See [configuration and observed limits](NAVIGATION_POLICY.md).
- **Opening and shutdown:** cancellation tracks resources arriving after the caller stops waiting. Disposal has a bounded result and explicitly reports incomplete cleanup; unresolved external CDP creation can retain a connection for late owned-page cleanup without closing unrelated pages.
- **Verification efficiency:** observed form values can be checked by ref without inferred selectors; document/node guards and a final value reread revoke outdated evidence. Agent guidance reuses current action snapshots. Model requests omit exact duplicate MCP text while preserving complete audit records.
- **Long-task recovery:** version-3 checkpoints bind registered tool contracts and trusted principal/tenant/policy identity, with strict unbound migration of valid version-1/2 files. Changed identities or contracts cannot be waived by reconciliation. Private atomic CLI persistence, fresh-observation/verification gates, system-policy inheritance, required acceptance-hook continuity, planner-only retries/fallback, deterministic history compaction and stall feedback remain supported. Uncertain mutations require explicit reconciliation and are never automatically replayed; bound custom-tool runs resume through the SDK that reconstructs their handlers.
- **Comparison infrastructure:** 16 development tasks with server/file judges, isolated resets, source/dist/task/judge hashes, pinned Browser Use adapter, HTTP or shared Codex CLI inference, measured usage and bounded process cleanup. The newest task checks an authenticated network response after a synthetic cross-origin authorization popup. Reports distinguish independent business acceptance, observed Agent completion and deadline-bounded full return; default Browser Use judging is retained and measured separately. Scripted and real-model attempts remain separately labeled.
- **Codex terminal handling:** the bridge keeps generic error notifications as diagnostics and waits for the same process's terminal outcome. A valid response now also requires a completed turn and successful process exit; timeout, cancellation and external-tool interception remain enforced. Historical failures are retained unchanged.

## Remaining work toward the full goal

The capability and evaluation contract is in [Browser Use comparison](BROWSER_USE_COMPARISON.md), supplemented by the [Agent/MCP/Harness/Pi/cloud variants audit](BROWSER_USE_VARIANTS.md). The audit identifies distinct comparison tracks rather than a measured whole-product ranking. Current gaps include:

1. Broader unknown long-running tasks, virtualized and authenticated applications, production authorization/popup return flows and repeated recovery under real models.
2. Broader service/model coverage and live validation of the new provider integrations, durable run/usage aggregation, configurable policies and trace/replay debugging.
3. Broader advanced-site extensions and real-model evaluation of custom-tool workflows. Typed registration, exact-origin filtering, trusted application context and recovery binding are implemented; this does not establish extensibility parity across Browser Use's broader ecosystem.
4. Broader network and file-access limits, scoped secret handling and full persistent-profile/tenant behavior. The owned profile now persists durable browser storage across a process restart, but same-origin account switching, production login and model-driven resume are unverified. The exact-origin document-navigation policy addresses only part of permissions and is unavailable with persistent profiles; it does not restrict subresource traffic or provide a network firewall.
5. A frozen broader task set, matched repeated runs, failure analysis and uncertainty reporting. Small smoke results cannot establish a cross-product win.
6. Broader platform verification for the expanded release and appropriate distribution; the current macOS clean-install check has passed.
7. Execute the additional official MCP, Harness, Pi and cloud comparison tracks under disclosed controls before any product-wide superiority claim.
